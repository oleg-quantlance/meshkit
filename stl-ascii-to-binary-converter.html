What the STL ASCII ↔ Binary Converter Does

Every .stl file is one of two encodings. ASCII STL is human-readable text — facet normal, outer loop, three vertex lines — and is what many CAD exporters, scanners and scripts write by default. Binary STL packs the same facets into fixed 50-byte records after an 80-byte header, loads far faster, and is 4–6× smaller. This tool detects which one you have, re-encodes it to the other (or to the encoding you choose), and reports the facet count, the exact byte sizes and the size ratio.

The geometry is not touched: same triangles, same order, same coordinates (ASCII output uses six-digit exponent notation, binary stores IEEE-754 float32, which is what both formats have always used). Facet normals are recomputed from the vertex winding, which fixes files whose stored normals disagree with their triangles. The conversion runs in a Web Worker in your browser; nothing is uploaded.

How to Convert in 3 Steps

  1. Drop the .stl: The sniffer checks the binary size identity (84 + 50 × N) before falling back to a text parse, so files that start with "solid" but are really binary are handled correctly.
  2. Choose the target: Auto flips to the other encoding. Force Binary to shrink a file for a slicer or upload, or ASCII when a script, a course assignment or a diff tool needs readable text.
  3. Export: Review facets, bounding box and the size ratio in the log, then click Export re-encoded .STL. The download is named name-binary.stl or name-ascii.stl so you keep the original.

Worked Example: Size of the Two Encodings

Binary STL = 80-byte header + 4-byte uint32 count + N × (12 normal + 36 vertices + 2 attribute) bytes = 84 + 50 N
ASCII STL ≈ N × 7 lines × ~30–45 characters ≈ 220–300 N bytes
N = 100,000 facets: binary 5.0 MB vs ASCII 22–30 MB (×4.4–6)
Binary parse: one typed-array read  ·  ASCII parse: ~700,000 tokens to scan

When You Need Which Encoding

  • Binary for slicers (Bambu Studio, OrcaSlicer, PrusaSlicer, Cura), print services, Printables/Thingiverse uploads and anything with a size limit. Some upload forms silently reject ASCII STL above a few megabytes.
  • ASCII for inspecting a mesh in a text editor, version control diffs, teaching, generating STL from scripts, and a few legacy CAM and FEA importers that choke on binary.
  • Either, but smaller: if size is the real problem, convert to 3MF, which indexes shared vertices and compresses the result.

Technical Limitations

The 2-byte per-facet attribute field (used by a few tools for colour) is written as zero in binary output. ASCII solid names are replaced by meshkit_export. Multi-solid ASCII files are read as one mesh. The tool does not repair geometry — open edges, flipped faces and duplicate triangles pass through unchanged; use STL Repair for that.

Frequently Asked Questions

My file starts with "solid" — isn't that ASCII?

Not necessarily. Many binary exporters (SolidWorks, some Blender add-ons) write "solid" in the 80-byte header. The converter checks whether the byte length equals 84 + 50 × N first; that identity is the reliable test. The log tells you what was detected.

Does converting change precision?

Binary STL stores float32, and ASCII STL written by nearly every tool also carries float32 precision (six to seven significant digits). Round-tripping ASCII → binary → ASCII reproduces the same values; only the text formatting differs.

Why is the binary file exactly 684 bytes for a cube?

A cube is 12 triangles: 84 + 50 × 12 = 684. You can verify any binary STL this way — if the size does not match the count in the header, the file is truncated or not binary.

Can I batch-convert many files?

One file at a time in this free tool. Drag the next file in as soon as the first download starts; conversion takes well under a second for typical parts.

Is anything uploaded?

No. Detection, parsing and re-encoding happen in a Web Worker in your browser. The export is generated from memory as a download.

Reference // How the Encoding Is Detected

A binary STL is exactly 84 + 50 × N bytes, where N is the uint32 at offset 80. The checker verifies that identity first; only when it fails does it try to read the file as text. Many binary exporters start the 80-byte header with the word solid, so the prefix alone proves nothing.
